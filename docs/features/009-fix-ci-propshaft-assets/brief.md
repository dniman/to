# Бриф: Propshaft::MissingAssetError в CI-тестах

**Issue:** #9

## Что делаем

Устраняем падение CI-прогона из-за ошибки `Propshaft::MissingAssetError: The asset 'application.js' was not found in the load path` в request-тестах и тестах лейаутов.

В CI ассеты JS не попадают в `public/assets` перед запуском `bundle exec rspec`, поэтому Propshaft не находит `application.js` при рендеринге лейаута. Локально проблема не воспроизводится, т.к. ассеты уже собраны предыдущими запусками.

Цель — сделать CI зелёным за счёт корректной работы Propshaft в test-окружении при чистом чекауте.

## Зачем

Сейчас CI красный на ветке `main`: request-тесты и тесты лейаутов не проходят. Это блокирует слияние любых PR с валидной проверкой, снижает доверие к CI и вынуждает мержить изменения без подтверждённого прогона тестов.

## Scope

**Входит:**
- Изменения в `.github/workflows/ci.yml` и/или конфигурации test-окружения, после которых шаг `bundle exec rspec` в CI не падает с `Propshaft::MissingAssetError`
- Сохранение корректной работы локальных запусков тестов (никаких регрессий на dev/test локально)

**Не входит:**
- Переход на другой asset pipeline (sprockets, importmap replacement и т.п.)
- Изменения фронтенд-стека (Tailwind, JS-тулчейн) сверх необходимого для сборки ассетов
- Оптимизация времени CI, кеширование ассетов между прогонами
- Изменения в самих тестах (подмена хелперов, стабы на `javascript_include_tag` и т.п.)

## Критерии приёмки

- При запуске CI workflow на чистом чекауте — шаг `bundle exec rspec` завершается без `Propshaft::MissingAssetError`
- При запуске CI workflow на чистом чекауте — весь job `test` завершается успешно (exit 0), регрессий по другим тестам нет
- При локальном запуске `bundle exec rspec` после выбранного фикса — все существующие тесты проходят без изменения их кода
- При ручной проверке приложения в dev-режиме после фикса — рендеринг лейаутов и загрузка `application.js` работают без регрессий

## Допущения

- CI-раннер эфемерный: `public/assets` не сохраняется между прогонами, поэтому каждый запуск начинается с отсутствующим манифестом ассетов
- Локальное прохождение тестов объясняется остаточными артефактами сборки в `public/assets` от предыдущих запусков `bin/dev` / `assets:precompile`
- Падение воспроизводится именно на `application.js`; других отсутствующих ассетов в ошибках не наблюдается

## Открытые вопросы

- Какой из путей выбрать для фикса (решение — на этапе спецификации с учётом скорости CI и точности воспроизведения прод-поведения в тестах). Список неисчерпывающий:
  - (а) добавить `bin/rails assets:precompile` шагом в CI перед `rspec`
  - (б) настроить Propshaft/тестовое окружение так, чтобы отсутствие ассета не вызывало ошибку
  - (в) создать минимальный placeholder `application.js` (или fixture-манифест), достаточный для работы Propshaft в test
  - (г) отключить digest/asset-lookup для test-окружения
- Ссылка на конкретный failing CI run и точный список падающих спеков (`spec/requests/...`, `spec/views/layouts/...`) — зафиксировать до старта спецификации для воспроизведения baseline
